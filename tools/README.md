# Thai Dividend Almanac — data pipeline

## กฎข้อเดียวที่ห้ามผิด

**ไม่มี LLM ตัวไหนอยู่ในเส้นทางของตัวเลข** ไม่ใช่แค่ Claude — ChatGPT, Gemini และ Grok ก็ห้ามเหมือนกัน
ราคาหุ้นเป็นข้อมูลที่มีคำตอบเดียว การให้โมเดลภาษาพูดตัวเลขออกมาคือการเปิดช่องให้ตัวเลขที่ดูสมจริงแต่ผิดหลุดขึ้นเว็บ
สคริปต์ทั้งสองตัวในโฟลเดอร์นี้จึงไม่เรียก API ของ AI เลย และไม่กิน quota ของ subscription ใด ๆ

subscription ที่คุณมี (ChatGPT / Gemini Pro / Grok) เอาไปใช้กับชั้นเล่าเรื่องได้ เช่น สรุปข่าวรายสัปดาห์
เขียน bull/bear ใหม่ หรืออ่าน filing — แต่ output ของมันไม่มีสิทธิ์เขียนลงช่อง price, eps, dps, bvps

## สามชั้นข้อมูล

| ชั้น | ไฟล์ | ความถี่ | ใครอัปเดต |
|---|---|---|---|
| ราคา | `snapshot.json` | รายวัน อัตโนมัติ | `update_snapshot.py` ผ่าน cron |
| ปัจจัยพื้นฐาน (EPS, BVPS, DPS) | `tools/fundamentals.json` | ไตรมาสละครั้ง หลังงบออก | คุณ แก้มือ |
| ประวัติ 2016–2025 | ฝังอยู่ใน HTML | ปีละครั้ง | `verify_history.py` แล้วเอาผลมาแก้ |

หน้าเว็บโหลด `snapshot.json` จาก origin เดียวกันเอง ผู้เข้าชมไม่ต้องใส่ key อะไรทั้งนั้น
ถ้าไม่มีไฟล์หรือโหลดไม่ได้ หน้าเว็บจะใช้ค่าที่ฝังไว้และขึ้นสถานะ ⚪ ให้เห็น

## ติดตั้ง

```
เว็บไซต์ของคุณ/
├─ index.html              ← thai_dividend_almanac_2026-09-22.html
├─ snapshot.json           ← สคริปต์เขียนทับทุกวัน
└─ tools/
   ├─ update_snapshot.py
   ├─ verify_history.py
   ├─ fundamentals.json
   └─ seed_history.json
```

GitHub Actions: เอา `update-snapshot.yml` ไปไว้ที่ `.github/workflows/` ไม่ต้องตั้ง secret ใด ๆ
Vercel Cron ก็ใช้แทนได้ แต่ GitHub Actions ให้ของแถมที่ Vercel ไม่ให้ คือ git history ของ `snapshot.json`
ซึ่งเท่ากับ audit log ของทุกราคาที่หน้าเว็บเคยแสดง ย้อนดูได้ฟรี

## รันครั้งแรก

```bash
python3 tools/update_snapshot.py --selftest   # ไม่แตะเน็ต ทดสอบ guard
python3 tools/update_snapshot.py --dry-run    # ยิงจริง แต่ไม่เขียนไฟล์
python3 tools/update_snapshot.py              # เขียน snapshot.json
```

ดู `--dry-run` ให้ครบ 24 ตัวก่อนค่อยเปิด cron ถ้ามีตัวไหนขึ้น `failed` แปลว่า symbol ผิดหรือแหล่งไม่มีหุ้นตัวนั้น

## Guard ที่ติดตั้งไว้

| เงื่อนไข | ผลลัพธ์ |
|---|---|
| ราคา ≤ 0 หรือดึงไม่ได้ | ใช้ค่ารอบก่อน ติดธง `stale` ขึ้น exit code 1 |
| quote เก่ากว่า 5 วัน | เหมือนกัน — ตลาดปิดยาวหรือหุ้นถูกพัก |
| ราคาขยับเกิน 15% จาก prevClose | ปฏิเสธ ใช้ค่ารอบก่อน ขึ้น exit code 1 |
| snapshot ส่งค่าเพี้ยนมาถึงหน้าเว็บ | หน้าเว็บมี guard ชั้นสอง ปฏิเสธและขึ้น 🔴 พร้อมชื่อหุ้น |

ตัวเลขทั้งสองชั้นตั้งใจให้ซ้ำกัน เพราะชั้นเดียวเคยพลาดมาแล้ว

## ปรับเมื่อแหล่งข้อมูลเปลี่ยน

แหล่ง quote เป็น endpoint สาธารณะที่ไม่มีสัญญารองรับ วันหนึ่งมันจะพัง
เวลานั้นแก้แค่ `QUOTE_URL` กับฟังก์ชัน `quote()` ในไฟล์เดียว ส่วนอื่นไม่ต้องแตะ
ถ้าจะเปลี่ยนไปใช้ฟีดที่มีสัญญาจริง (SET SMART, ผู้ให้บริการข้อมูลรายปี) ก็แทนที่จุดเดียวกันนี้

## verify_history.py

```bash
python3 tools/verify_history.py                  # ครบ 24 ตัว
python3 tools/verify_history.py SCB KBANK KTB    # เฉพาะตัวที่ drift สูง
```

ได้ไฟล์ออกมาสองอัน

- `history_diff.md` — ตารางรายปีเฉพาะปีที่ seed กับแหล่งไม่ตรง
- `history_verified.json` — ชุดราคาสิ้นปีและปันผลรายปีที่พร้อมเอาไปแทนใน HTML

**ข้อควรระวังสามข้อ**

1. ราคาในแหล่งเป็น adjusted ถ้าหุ้นเคยแตกพาร์ ตัวเลขจะไม่เท่ากับราคาที่เห็นบนกระดานในปีนั้น สคริปต์จะเตือนเมื่อเจอ split และให้ทั้ง `prices` กับ `prices_adj` มาเทียบ
2. ปันผลรายปีมีสองฐาน ฐาน ex-date กับฐาน fiscal ซึ่งฐาน fiscal เป็นการเดาว่าปันผลที่ XD เดือน ม.ค.–มิ.ย. เป็นของปีก่อนหน้า ใช้ตัดสินใจไม่ได้จนกว่าจะเทียบกับประกาศจริง
3. ปันผลพิเศษกับปันผลเป็นหุ้นมักหายหรือเพี้ยนในแหล่งฟรี ชื่อที่รู้อยู่แล้วว่าเสี่ยงคือ ADVANC และ TIDLOR

ดังนั้นผลของสคริปต์คือ **รายการที่ต้องไปเช็คต่อ** ไม่ใช่ความจริงสำเร็จรูป ปีที่ขึ้นธงให้เปิดหน้านักลงทุนสัมพันธ์
หรือประวัติ XD ของ SET ยืนยันก่อนแก้ลง HTML

## ทุกไตรมาส

หลังงบออก (ปลาย ก.พ. / พ.ค. / ส.ค. / พ.ย.) แก้ `fundamentals.json` สามช่องต่อหุ้น คือ `eps_ttm`, `bvps`, `dps_ttm`
แล้ว cron วันถัดไปจะคำนวณ P/E, P/BV, Yield ใหม่ให้เอง ถ้าไม่แก้ ราคาจะสดแต่ตัวหารจะค้าง — P/E จะเพี้ยนแบบเงียบ ๆ
ตั้งเตือนไว้ในปฏิทินเลย
